ARCHITECTURE
------------
Inference:
  Jack Orchestrator / Primary Pi -> Jack :8001/v1 -> Jack-selected backend/model

Supervision:
  Jack Orchestrator -> Jack :8001/jack/orchestration
                    -> private Pi bridge :8013
                    -> privileged Primary Pi

Jack Orchestrator is cognition-capable but execution-restricted. It does not need
direct filesystem, shell, process, backend, :8013, controlToken, or Primary-Pi
configuration access. Primary Pi remains the privileged worker.

Gateway v2 governs the supervisor-to-worker control path. It does not claim to
intercept every privileged filesystem/shell/process action available inside
Primary Pi.

RUN-BOUND TRANSPORT
-------------------
- independent task UUID and runId
- private dispatch marker stripped before model-visible prompt processing
- binding through input -> before_agent_start -> agent_start
- positive message/tool attribution only while a run epoch is open
- automatic retry retains runId and increments runEpoch
- agent_end clears low-level attribution immediately
- agent_settled is physical control-run closure
- unowned events retain null task/run identity

JACK EVENT ENVELOPE
-------------------
- process-local monotonic seq
- task_id / run_id / run_epoch / attribution promotion
- source="pi"
- source_at and jack_received_at
- data plus preserved source_event
- bounded replay, default 512 events
- Last-Event-ID / ?after=<seq>
- explicit HTTP 409 orchestration_replay_gap

CANCELLATION / SETTLEMENT
-------------------------
Cancellation is immediately visible but physical settlement is separate. No new
controlled task is admitted while the cancelled control run remains unsettled.
The final accepted bridge clears control-run authority before emitting the
terminal settlement snapshot, so settledAt and runOpen=false are consistent in
SSE and status views.

CONCURRENCY
-----------
Jack's existing inference semaphore is the backend concurrency authority. With
the saved launcher setting Maximum concurrent Kernel requests = 2, live LM
Studio logs proved:

- two simultaneous direct Jack inference requests; and
- simultaneous Jack Orchestrator inference plus Primary Pi worker inference.

No concurrency architecture patch was required. The important configuration
precedence fact is that the saved launcher value is written into the child server
environment and therefore overrides a parent-shell-only JACK_MAX_CONCURRENT value.
